## Goal

Verify the Extension still works correctly after the ParaSpell integration is updated to API **v2** — mainly that XCM transfers keep working on every supported route, with correct fees and balances.

## Background

This story covers [issue #5051](https://github.com/Koniverse/SubWallet-Extension/issues/5051) — *"Update ParaSpell API integration to v2"*: align the current ParaSpell integration with the latest API version.

ParaSpell is the library the Extension uses to build XCM transfers, so this is a **regression-heavy** change: the feature list stays the same, but the code path underneath every XCM transfer is new. The main risk is a route that silently stops working, a wrong fee, or a stuck transfer — not a new UI.

This is the **QC side** of the change. The dev-side story is [US-13.18](US-13.18-paraspell-http-api-v2.md) in EPIC-13, which describes the code migration itself (moving every ParaSpell HTTP call from `/v1` to `/v2`) and is owned by the developer. This story only covers testing the result.

## Things to check

- [ ] AC-1: XCM transfer works on relay chain to parachain routes (e.g. Polkadot → Asset Hub)
- [ ] AC-2: XCM transfer works on parachain to relay chain routes (e.g. Asset Hub → Polkadot)
- [ ] AC-3: XCM transfer works on parachain to parachain routes (e.g. Asset Hub ↔ Hydration)
- [ ] AC-4: The network fee shown on the confirm screen is correct for each route tested
- [ ] AC-5: Balances update correctly on both source and destination chains after each transfer completes
- [ ] AC-6: Transfer history records the XCM transfer correctly
- [ ] AC-7: Error cases still behave properly — not enough balance, amount below the destination's minimum, unsupported route — with a clear message and no stuck screen
- [ ] AC-8: XCM deposit into an earning position still works (if the route supports it)
- [ ] AC-9: AC-1 to AC-8 hold on a **fresh install** (no prior version/data)
- [ ] AC-10: AC-1 to AC-8 hold on an **upgrade** from a previous version (existing accounts/data carried over)
