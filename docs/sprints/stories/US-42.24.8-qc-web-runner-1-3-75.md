## Goal

Check the user-configurable Subscan API key in Settings, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

User-configurable Subscan API key ([#4965](https://github.com/Koniverse/SubWallet-Extension/issues/4965)) — a field in Settings where a user puts their own Subscan API key. It is hidden as you type with an eye toggle to reveal it, stored encrypted, and sent as a header on every Subscan request.

## Before testing

- A valid Subscan API key.
- An invalid string, to check what happens when the key is wrong.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [x] AC-1: The API key field is in Settings, hidden as you type, and the eye toggle reveals and hides it — Android + iOS fresh
- [x] AC-2: A valid key saves, and it is still there after closing and reopening the app — Android + iOS fresh
- [x] AC-3: With a valid key saved, the features that use Subscan work — balances and history load — Android + iOS fresh
- [x] AC-4: The key is not shown anywhere it should not be, such as logs or an export — Android + iOS fresh
- [x] AC-5: An invalid key gives a clear message rather than a silent failure — Android + iOS fresh
- [x] AC-6: The key can be cleared, and the app falls back to working without one — Android + iOS fresh
- [x] AC-7: AC-1 to AC-6 pass on Android + iOS upgrade
- [x] AC-8: After upgrading, a key saved before the upgrade is still saved and still works — both platforms

## Steps

- [x] TASK-1 — Note the build under test and its web-runner version
- [x] TASK-2 — Android + iOS fresh install: enter, reveal, save, restart, use, clear (AC-1 to AC-6)
- [x] TASK-3 — Android + iOS upgrade from the previous version: repeat, then check the saved key carried over (AC-7, AC-8)
- [x] TASK-4 — Log any bugs found in the manual test report
