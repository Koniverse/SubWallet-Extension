## Goal

Recheck every bug found while testing the web-runner update, once the developer has fixed it. One place to see what is still open and what has been confirmed fixed.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## How this works

The version sub-tasks record what a build did on the day it was tested. Their checkboxes and bug tables are not edited again — that is the record of that run.

This story is where the bugs get rechecked later. Every bug logged in any of the sub-tasks gets a row in the table below as soon as it is found. When the developer says a bug is fixed, it gets retested here on the new build and the row is updated with the result.

A bug that fails the recheck stays open and goes back to the developer. A bug that passes is confirmed fixed here; the original sub-task keeps its own record unchanged.

Verifying the bug is only half of it. A bug that left an AC failed or blocked means that check never got a verdict, so once the bug is fixed that AC has to be rerun here too. The bug closing says the defect is gone; the AC rerun says the thing the AC was checking actually works. The table below lists both, with each AC written out in full under the bug holding it up.

## Before testing

- A build with the fix in it, and confirmation from the developer of which bugs it covers.
- The same test data the bug was originally found with — the account, the network, the token. Without it the recheck is not the same test.

## Things to check

- [ ] AC-1: Every bug marked fixed by the developer is retested on the new build, on the platform it was found on
- [ ] AC-2: A bug that passes the recheck is confirmed fixed in the table above, with the build it was verified on
- [ ] AC-3: A bug that still reproduces stays open and goes back to the developer, with what was seen on the new build
- [ ] AC-4: Every AC that the bug left failed or blocked is rerun here on the fixed build — the bug closing is not enough on its own
- [ ] AC-5: An AC that passes on the rerun is recorded as settled, naming this story and the build it was rerun on; the original sub-task keeps its own record unchanged
- [ ] AC-6: An AC that still fails on the rerun stays failed, and the bug goes back to the developer
- [ ] AC-7: The fix did not break anything around it — the screens the bug touched still work
- [ ] AC-8: Bugs found on both platforms are rechecked on both
