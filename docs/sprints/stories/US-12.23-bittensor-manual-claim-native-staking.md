## Why EPIC-12 owns it

[EPIC-12](../epics/EPIC-12.md) is **Staking & Earning**, and Bittensor is already its territory:
[US-12.6](US-12.6-bittensor-dtao-subnet-staking.md) (dTAO subnet staking, `done`),
[US-12.10](US-12.10-bittensor-alpha-token-liquid-staking.md) (alpha-token liquid staking, `backlog`)
and [US-12.11](US-12.11-trusted-stake-alpha-index.md) (Trusted Stake, `review`).

"Native staking" here most likely means root-network TAO staking as opposed to the subnet/alpha
paths those stories cover — but the issue does not say so.

## Open questions

1. **What is not automatic today?** "Manual claim" implies rewards currently accrue without a
   user-triggered claim, or that a claim exists but is not surfaced. Which one decides whether this
   is a UI change or a new extrinsic path.
2. **Which reward type?** Root-network TAO staking rewards, subnet emissions, or dTAO alpha —
   [US-12.6](US-12.6-bittensor-dtao-subnet-staking.md) already covers subnet staking, so the overlap
   needs settling before scoping.
3. **Does it interact with the deprecated root claim type?** v1.3.86 removed a deprecated Bittensor
   root claim type (#5045, [US-12.21](US-12.21-earning-fixes-recovered-from-uncategorized.md)). If
   this asks to reintroduce a claim path there, that history matters.
4. **Priority.** No label, no assignee, no milestone. `P3` here is a placeholder, not a decision.
