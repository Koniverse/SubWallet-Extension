## Goal

Track the QC of the web-runner update to 1.3.86 on SubWallet Mobile. The work is split by web-runner version — one sub-task per version — plus one sub-task for the full regression pass.

## Background

This story covers [issue #2057](https://github.com/Koniverse/SubWallet-Mobile/issues/2057) — "Update web-runner 1.3.86" on the SubWallet-Mobile repo.

The issue lists 18 web-runner versions, from 1.3.68 to 1.3.86, and the Extension issues that went into each one. Mobile runs the Extension code through the web-runner, so every one of those changes reaches Mobile when the runner is updated — which is why they all have to be checked here even though they were tested on Extension when they first shipped.

Version 1.3.81 is not in the issue; the list goes from 1.3.80 straight to 1.3.82. Kept as written, nothing added.

## How the work is split

One sub-task per web-runner version (18 of them), plus [US-42.24.19](US-42.24.19-qc-web-runner-regression.md) for the regression pass.

Each version sub-task checks only the content of that version, on four combinations:

1. Android — fresh install
2. Android — upgrade from the previous version
3. iOS — fresh install
4. iOS — upgrade from the previous version

The full wallet regression checklist lives only in US-42.24.19, so it is written once instead of repeated in 18 files.

## How the points were set

Points are the cost of running the test session, on the shared Fibonacci scale, weighing four things: how many separate places have to be checked, what has to be set up before testing can start, whether verifying means looking at one screen or reconciling numbers across several, and whether anything external can block the session part-way.

| Points | Roughly |
| --- | --- |
| 2 | under half a day, one screen, data already there |
| 3 | about half a day |
| 5 | about a day |
| 8 | about two days, or a day plus data the tester has to create |
| 13 | several days, or a session that an external dependency can block |

The four 13s are the ones with an external blocker: OpenGov waits on a lock period, Bittensor root staking waits on a reward cycle that lands at a random time roughly once a day, Proxy needs on-chain delegations set up across permission levels, and the 1.3.78 Bittensor group needs real TAO and Alpha on more than one subnet.

Points are set before the session runs and are not adjusted afterwards.
