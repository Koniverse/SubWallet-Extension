## Goal

Run the whole wallet once the web-runner is on 1.3.90, to catch anything the per-version checks missed. Android and iOS, fresh install and upgrade.

Round 3 is open, on the build going to beta. The rounds before it are described under the checklist.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-90.md).

## Why this is its own sub-task

The eighteen version sub-tasks each check only what changed in that version. This one checks that the wallet as a whole still works after eighteen versions of changes land at once. The checklist lives here and only here, so it is written once instead of being copied into eighteen files where the copies would drift apart.

Run it after the version sub-tasks, on a build with the web-runner already at 1.3.90.

## Before testing

- Accounts covering the main types: created in the app, imported by seed phrase, imported by private key, and a watch-only account if the app supports one.
- Balances on several chains — at least one substrate chain, one EVM chain, and Bittensor.
- NFTs on an EVM chain and on Unique Network.
- An existing staking position and an existing earning position.
- A dApp to connect to.
- The previous version installed with data on it, for the upgrade runs.

## Regression checklist

Round 3, opened 2026-09-30. Android and iOS have a list each, carrying the same lines — REG-A for Android, REG-I for iOS. Tick a line only when it passes on that platform, on both a fresh install and an upgrade.

### Which round this is

Round 3 prepares the TestFlight build. Round 2 ran against web-runner versions as each one landed; the beta is one build carrying all of them, so the lines are run again on it.

Ticks are cleared, lines and numbering are not. Next is [US-42.27](US-42.27-qc-release-mobile.md), the release gate on the beta and production builds.

Transfer is one section with a line per token family — EVM, substrate, BTC, TON — each covering single-chain and cross-chain, native and local. It used to be three sections with single-chain and cross-chain split across them, though a tester runs both from the same screen.

Four features had no line and now do: import from Trust Wallet, transfer through a bridge, parachain (collator) staking, and change validator. Each is QC'd in its own version sub-task — Trust Wallet in [US-42.24.4](US-42.24.4-qc-web-runner-1-3-71.md), the bridge in [US-42.24.11](US-42.24.11-qc-web-runner-1-3-78.md), parachain earning in [US-42.24.6](US-42.24.6-qc-web-runner-1-3-73.md) — so they are in the build; the regression never swept them.

REG-70 and REG-82 are separate because migrating solo accounts to a unified account and typing in a Subscan API key have nothing to do with each other. The migration rewrites how keys are stored and can leave an account unable to sign if it is interrupted ([LESSONS §71](../../LESSONS.md)); the API key is a string in settings. On one line neither could be ticked until both had run.

REG-83 checks Crowdloans is gone on a fresh install. REG-77 names it too, but only looks after an upgrade and covers four removed features at once.

REG-84 checks the account details screen itself. The screen was only ever reached on the way somewhere else — REG-3 derives from it, REG-8 opens it for a multisig — so what it displays had no check of its own: the name, the address per network with its QR code and copy button, and the badges saying whether the account is unified or solo and what type it is.

REG-85 checks that the app survives being backgrounded. Round 1 had this check and round 2 lost it in the rewrite, which left BUG-42.24.19-06 — the app hanging on a loading screen after a spell in the background — with nothing to confirm against once it is fixed. The bug's entry in [US-42.24.20](US-42.24.20-qc-web-runner-verify-bugs.md) still points at round 1's numbering for that reason.

REG-32, "Remove a custom NFT", is skipped. NFTs are auto-detected now, so a removed one comes straight back and the action does nothing. The line stays so a reader sees why it no longer applies.

REG-76, the transaction history from before an upgrade, is skipped as well. The API key Polkadot used to provide no longer works, so there is no history to read the check against. Adding a key still works — REG-74 and REG-82 both pass — it is the key itself that is gone, which is outside the build.

Governance is not covered: Mobile has no governance screen.

Each list holds 85 lines, two of them skipped. Round 1's list and results are gone and round 2's ticks are cleared; the bugs both rounds found are kept below.
