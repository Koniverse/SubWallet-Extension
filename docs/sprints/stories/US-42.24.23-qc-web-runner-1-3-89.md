## Goal

Check the one item that came into the web-runner with 1.3.89, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-90.md).

## What is in this version

Repoint KAH↔PAH XCM refs ([#5062](https://github.com/Koniverse/SubWallet-Extension/issues/5062)) — a P0. The USDt route between Kusama Asset Hub and Polkadot Asset Hub pointed at the wrong references, and a real transfer had already been stranded by it. The fix spans two repos: the chain-list data ([ChainList PR #709](https://github.com/Koniverse/SubWallet-ChainList/pull/709)) and a guard in [PR #5063](https://github.com/Koniverse/SubWallet-Extension/pull/5063).

This was QC'd on Extension in [US-42.22](US-42.22-qc-issue-5062-repoint-kah-pah-usdt-xcm.md), 15 of 15 AC with no bugs, and both halves of the fix were confirmed in the build there. Mobile runs the same Extension code through the web-runner, so the checks are the same; what this story adds is that they hold on the Mobile build.

The point that shaped the Extension run applies here too. Neither half alone closes the P0 — a guard that blocks the route is not the same as data that routes correctly — so AC-4 checks which halves the Mobile build actually carries rather than assuming both.

## Before testing

- USDt on Kusama Asset Hub and on Polkadot Asset Hub, enough to send in both directions.
- Native balance on both chains for fees.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [ ] AC-1: A USDt transfer from Kusama Asset Hub to Polkadot Asset Hub arrives, with the right amount — Android + iOS fresh
- [ ] AC-2: The same works in the other direction, Polkadot Asset Hub to Kusama Asset Hub — Android + iOS fresh
- [ ] AC-3: The fee quoted before sending matches what is taken, on both directions — Android + iOS fresh
- [ ] AC-4: Confirm which halves of the fix are in the Mobile build — the chain-list data, the guard, or both. If only the guard shipped, the route must be blocked in the UI and the data confirmed as still wrong but unreachable, not assumed fixed — Android + iOS fresh
- [ ] AC-5: Tokens never leave the source chain on a route that cannot deliver them — this is the failure the P0 was raised for — Android + iOS fresh
- [ ] AC-6: AC-1 to AC-5 pass on Android + iOS upgrade

## Steps

- [ ] TASK-1 — Note the build under test and its web-runner version
- [ ] TASK-2 — Confirm which halves of the fix the build carries (AC-4)
- [ ] TASK-3 — Android + iOS fresh install: run the route both ways, check fees and arrival (AC-1 to AC-3, AC-5)
- [ ] TASK-4 — Android + iOS upgrade from the previous version: repeat (AC-6)
- [ ] TASK-5 — Log any bugs found in the manual test report
