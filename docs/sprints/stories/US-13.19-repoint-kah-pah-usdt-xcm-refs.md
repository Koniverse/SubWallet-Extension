## Goal

Stop the wallet offering a Kusama-Asset-Hub → Polkadot-Asset-Hub XCM route for an asset that
cannot cross the bridge. Sending it **traps the funds on the destination chain**.
[#5062](https://github.com/Koniverse/SubWallet-Extension/issues/5062).

## Background — the route strands the tokens it moves

`statemine-LOCAL-USDt` is the **Kusama-AH-native** USDt (`assets` pallet, index `1984`).
`AssetRef.json` declares an XCM route from it to `statemint-LOCAL-USDt`. That asset cannot cross the
Polkadot↔Kusama bridge, so the transfer leaves the funds stranded on Polkadot Asset Hub.

> **This has already happened on a real transfer, not only in theory.** The tokens are **locked on
> the destination chain, not destroyed** — recovering them is a separate, manual exercise. It is
> **P0** because the wallet is still offering the route, so it can happen again.

It is the only P0 in [W35](../sprint-2026-W35.md).

Kusama Asset Hub carries **two** USDt and the wallet registers only the wrong one. The sibling asset
already models this correctly — `statemine-LOCAL-USDC` is declared `isBridged: true` with a
`parents: 2` location. **USDt is the odd one out**, which is the shape of a data-entry omission
rather than a design gap.

## The fix has two halves, in two repositories

This is the part worth reading carefully, because the issue and the pull request **do not describe
the same change**.

### Half 1 — chainlist data (`SubWallet-ChainList`) — **merged 2026-08-24**

[#5062](https://github.com/Koniverse/SubWallet-Extension/issues/5062) prescribes four data edits:

1. `ChainAsset.json` — add `statemine-LOCAL-USDt-Polkadot`: `symbol: USDt-Polkadot`, `decimals: 6`,
   `minAmount: 10000`, `priceId: tether`, `metadata.isBridged: true`, and a
   `parents: 2, X4[GlobalConsensus(Polkadot), Parachain(1000), PalletInstance(50), GeneralIndex(1984)]`
   location — values verified upstream against
   `/v2/supported-assets?origin=AssetHubKusama&destination=AssetHubPolkadot`.
2. `ChainAsset.json` — add the missing `multilocation` (`parents: 0, X2[PalletInstance(50), GeneralIndex(1984)]`)
   to `statemine-LOCAL-USDt`, which currently trips `validate-asset-refs`:
   *"Token must have multilocation: statemine-LOCAL-USDt"*.
3. `AssetRef.json` — repoint **both** directions at the bridged asset, leaving the KAH-native USDt
   with no XCM route at all.
4. `AssetLogoMap.json` — add `statemine-local-usdt-polkadot`.

## Acceptance criteria

- [x] **AC-1** — A KAH-native `statemine-LOCAL-USDt` XCM transfer to Polkadot Asset Hub is
  **refused**, not merely warned about, and the refusal names why. *(US-42.22, 15/15.)*
- [x] **AC-2** — The new user-facing string (added to all 5 locales) is what the user actually sees
  on that refusal — not a generic error. *(US-42.22.)*
- [x] **AC-3** — `statemine-LOCAL-USDt-Polkadot` exists in chainlist with `isBridged: true` and the
  `parents: 2` X4 location, and **is** routable KAH → PAH. *(ChainList PR #709, merged 2026-08-24;
  confirmed on the build by US-42.22.)*
- [x] **AC-4** — `validate-asset-refs` passes: `statemine-LOCAL-USDt` has a `multilocation`.
  *(ChainList PR #709; US-42.22.)*
- [x] **AC-5** — `statemine-LOCAL-USDC` behaviour is unchanged — it already modelled this correctly
  and must not regress. *(US-42.22.)*
- [ ] **AC-6** — A regression test covers the trapped-funds route, so this cannot silently return.

> **Five of six ticked 2026-09-03, on QC evidence.** PR #5063 merged 2026-08-27 (`dd96d076a5`) and
> shipped in **v1.3.89**; the chainlist half merged 08-24. AC-1 … AC-5 rest on
> [US-42.22](US-42.22-qc-issue-5062-repoint-kah-pah-usdt-xcm.md)'s 15/15 pass, **not** on any check
> this repository can run — if that page is wrong, these ticks are wrong with it ([D107](../../CONTEXT.md)).
>
> **AC-6 is deliberately left unticked and the story still ships.** No regression test was ever
> written. The route that stranded a real transfer is now guarded by data and by code, and by nothing
> executable — so the only thing standing between a future refactor and a repeat is this unticked box.

## Open

- **AC-6 — still no regression test.** The one item that did not land. Both halves shipped and QC
  confirmed them by hand; nothing executable defends the route. Carried into
  [W36](../sprint-2026-W36.md) as the open item on this story.
- **The two-repository split was the real hazard here**, and it nearly produced a false alarm in the
  opposite direction: this story spent nine days asserting the data half was missing when it had
  already merged. Anything spanning `SubWallet-Extension` and `SubWallet-ChainList` needs both repos
  searched, for **PRs as well as issues**, and by title as well as by number.
