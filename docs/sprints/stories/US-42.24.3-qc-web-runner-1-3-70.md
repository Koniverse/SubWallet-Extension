## Goal

Check OpenGov phase 1 — viewing referenda, voting, and governance token locks — together with the locked balance display that shows those locks. Android and iOS, fresh install and upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

OpenGov phase 1 ([#4678](https://github.com/Koniverse/SubWallet-Extension/issues/4678)), in three parts:

- Referenda — see the list with title, proposer, track and status; open a referendum and see its description, vote counts and timeline.
- Voting — cast a vote (aye, nay, abstain, split), change an existing vote, and remove a vote where allowed.
- Token locks — see how much is locked by governance per account, and unlock it once the lock period has passed.

This is the only item in [#2057](https://github.com/Koniverse/SubWallet-Mobile/issues/2057) still unticked, so the feature may not be complete in the build. Check what is there and record what is missing rather than filing everything absent as a bug.

The issue describes goals, not screens, so these checks are written from what the build does. If a written spec appears later, this story needs re-reading.

## Also tested here — locked balance display

Locked balance display ([#4708](https://github.com/Koniverse/SubWallet-Extension/issues/4708)) shipped in 1.3.68, not 1.3.70, and [US-42.24.1](US-42.24.1-qc-web-runner-1-3-68.md) is the sub-task for that version. It is tested here instead because the two belong together: tapping the Locked field opens a breakdown by lock type, and Governance is one of those types. Checking it without any governance lock in place would only cover part of it.

What it does: the breakdown splits locked funds into staking (active and inactive), governance, and others. The "others" figure is calculated as total locked minus the larger of staking and governance, and has a tooltip explaining it. Single account mode expands in place; all-accounts mode shows a per-account breakdown from the info icon.

## Before testing

- An account with enough DOT to vote and to cover the conviction lock.
- A referendum that is open at the time of testing — this is outside our control and may need waiting.
- For the unlock check, a governance lock that has already expired. If none exists, this part waits for a lock period to run out, which is days. Plan for it or record it as blocked.
- An account with tokens locked in more than one way at once — some staked and some locked by governance — so the locked balance breakdown can be checked with real numbers in each row. Voting during this session creates the governance side.

This is what makes the story a 13: the session can be stopped part-way by things outside the test.
