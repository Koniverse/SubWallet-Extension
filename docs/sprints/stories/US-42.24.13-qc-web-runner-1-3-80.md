## Goal

Check the four items that came into the web-runner with 1.3.80, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

- Transfer max at ED ([#2641](https://github.com/Koniverse/SubWallet-Extension/issues/2641)) — sending the maximum from an account whose balance equals the existential deposit used to fail. An old bug, from 2023.
- Wrong network address on XCM confirm ([#3936](https://github.com/Koniverse/SubWallet-Extension/issues/3936)) — the XCM confirmation screen showed the wrong network's address during swap and liquid staking.
- Token approve on XCM ([#4830](https://github.com/Koniverse/SubWallet-Extension/issues/4830)) — a token that had already been approved still sent the user to the approve screen instead of straight to the transfer confirmation.
- NFTService phase 1 ([#4884](https://github.com/Koniverse/SubWallet-Extension/issues/4884)) — the NFT logic for EVM and Unique Network moved into the SDK behind a new NFTService, including nested NFTs. The whole NFT area has to be checked again because the layer underneath changed.

## Before testing

- An account funded to exactly the existential deposit. This has to be topped up precisely; a little over or under and the case does not reproduce. This is the fiddly part of the story.
- An account that has already approved a token on an EVM chain, for the approve check.
- NFTs on an EVM chain and on Unique Network, including at least one nested NFT.
- Balance for XCM during a swap or liquid staking.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.
