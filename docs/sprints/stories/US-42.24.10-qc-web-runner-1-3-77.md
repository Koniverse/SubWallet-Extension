## Goal

Check the five items that came into the web-runner with 1.3.77, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

- Proxy improvements ([#4942](https://github.com/Koniverse/SubWallet-Extension/issues/4942)) — wording fixed when a proxy account is used for staking and unstaking, transfer max improved for proxy accounts, and some EVM network types removed from the list of networks that support proxy accounts.
- Multisig improvements ([#4963](https://github.com/Koniverse/SubWallet-Extension/issues/4963)) — the account picker when creating a multisig gets a search box, account type logos, and grouping by type; requests waiting for approval can be filtered by network type.
- PAH to KAH warning popup turned off ([#4954](https://github.com/Koniverse/SubWallet-Extension/issues/4954)) — the popup warned about a fee that is no longer accurate, since the real fee is far lower than the figure it quoted.
- stDOT sunset ([#4968](https://github.com/Koniverse/SubWallet-Extension/issues/4968)) — StellaSwap has shut down stDOT. The staking option is hidden in Earning, the stake more and unstake buttons are disabled or hidden on the position screen, and the position shows as not earning.
- chain-list stable v0.2.126 — four ChainList issues: replaced RPC endpoints for Avail Mainnet and Turing ([#680](https://github.com/Koniverse/SubWallet-ChainList/issues/680)), multisig support on Energy Web X and its Paseo testnet ([#686](https://github.com/Koniverse/SubWallet-ChainList/issues/686)), PRIME and EURC added on Hydration ([#687](https://github.com/Koniverse/SubWallet-ChainList/issues/687)), and swap support for both ([#688](https://github.com/Koniverse/SubWallet-ChainList/issues/688)).

## What is unticked, and one item that will not be done

The AC below were written from the four issue bodies on 2026-09-11, not from their titles. Several items inside them are still unticked on GitHub, so parts of this scope may simply not be in the build — record what is missing rather than filing it as a bug.

[#4942](https://github.com/Koniverse/SubWallet-Extension/issues/4942) has four unticked items: the wording for proxy on stake and unstake, the transfer max improvement, remembering the proxy account picked last time, and choosing which token pays the fee. The first three are marked "recheck, the UI is changed", and remembering the last proxy account has no AC here at all — the UI changed enough that the item no longer describes anything on screen. The fourth will not be done — the developer wrote that it cannot be handled while the signer is picked on the confirmation screen and the fee token on the send screen.

[#4963](https://github.com/Koniverse/SubWallet-Extension/issues/4963) has one unticked item, which is a link back to #4942. Everything else in it is ticked, including one that reverses an earlier decision: a multisig account now connects to a dApp and signs there. The issue's Expected block ends with "Message signing is not working", which reads as a defect still to fix rather than the wanted behaviour — AC-6a is written on the basis that message signing has to work.

[#4968](https://github.com/Koniverse/SubWallet-Extension/issues/4968) has one unticked item, marked optional: a popup explaining why a stDOT position was unstaked. Its absence is not a bug.

## Why this is 8 points with 29 AC

The AC count is high but the session is not. This version is a recheck: the proxy and multisig features were built and tested in full on 1.3.72 and 1.3.74, and what lands here is a handful of fixes and improvements on top of them. The accounts, proxies and multisigs all exist already, so most of the cost of those stories — setting up on-chain relationships and walking a transaction through each signatory — does not repeat.

Kept at 8 on 2026-09-11 for that reason, after the AC were rewritten from the issue bodies.

## Before testing

- Proxy accounts set up from 1.3.72, so the improvements can be checked without building them again.
- A multisig account with several signatories and at least one pending request, from 1.3.74.
- An account holding stDOT with an existing position — hard to create now that deposits are disabled, so use an account that already has one.
- Balance on both PAH and KAH to start a transfer between them.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.
