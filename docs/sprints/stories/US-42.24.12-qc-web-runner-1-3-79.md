## Goal

Check the four items that came into the web-runner with 1.3.79, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

Mostly cleanup after 1.3.78.

- Alpha price against TaoStats ([#4987](https://github.com/Koniverse/SubWallet-Extension/issues/4987)) — the alpha price was worked out from taoIn divided by alphaIn, which did not match what TaoStats showed. It now comes from currentAlphaPriceAll instead. A wrong price here confused users and could make earning fail.
- ParaSpell API v1 ([#4979](https://github.com/Koniverse/SubWallet-Extension/issues/4979)) — a new API base URL and a different request format, so XCM needs another pass.
- Issues after the 1.3.78 merge ([#4988](https://github.com/Koniverse/SubWallet-Extension/issues/4988)) — four display problems on the transfer confirmation and token approve screens: the fee value in the wrong colour and size, the amount and fee not lined up, a wrong value in the transfer amount input, and a missing network fee on the token approve screen.
- Swap Service refactor ([#4826](https://github.com/Koniverse/SubWallet-Extension/issues/4826)) — internal cleanup, SwapRequest replaced by SwapRequestV2 and dead code removed. Nothing visible, so it is checked by whether swap still works.

## Before testing

- Bittensor alpha holdings, to compare the price against TaoStats.
- Balance on both ends of an XCM route.
- A token that needs approving on an EVM chain, to reach the token approve screen.
- The Figma link in [#4988](https://github.com/Koniverse/SubWallet-Extension/issues/4988) open, to compare the screens against.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.
