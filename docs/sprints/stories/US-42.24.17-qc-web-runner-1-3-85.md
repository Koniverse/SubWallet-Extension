## Goal

Check the signing prompt security fix, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

Signing prompts could conceal the actual transaction ([#5042](https://github.com/Koniverse/SubWallet-Extension/issues/5042)) — a security fix following the same problem reported by the polkadot-js extension team. A signing request could be crafted so the prompt showed something other than what was really being signed.

This is a security check, not a display check. The point is that what the user sees on the signing screen is what actually gets signed.

## Before testing

- A dApp, or a test page, that can send a signing request with content designed to mislead. Without this, the fix cannot be tested at all — this is the whole setup cost of the story.
- WalletConnect or the in-app browser working, to reach the signing screen from outside.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [ ] AC-1: A normal signing request shows the right details — amount, destination, network, fee — Android + iOS fresh
- [ ] AC-2: A request built to hide its real content is shown for what it is; the prompt does not display something different from what would be signed — Android + iOS fresh
- [ ] AC-3: A request the app cannot decode safely is refused or clearly flagged, rather than shown as if it were understood — Android + iOS fresh
- [ ] AC-4: Signing a message, as opposed to a transaction, shows the real message content — Android + iOS fresh
- [ ] AC-5: Ordinary dApp signing still works and is not blocked by the fix — Android + iOS fresh
- [ ] AC-6: AC-1 to AC-5 pass on Android + iOS upgrade
- [ ] AC-7: After upgrading, existing dApp connections still work and their signing requests are shown correctly — both platforms

## Steps

- [ ] TASK-1 — Note the build under test and its web-runner version
- [ ] TASK-2 — Set up a dApp or test page that can send a misleading signing request; record what it sends
- [ ] TASK-3 — Android + iOS fresh install: normal request, misleading request, undecodable request, message signing, ordinary dApp signing (AC-1 to AC-5)
- [ ] TASK-4 — Android + iOS upgrade from the previous version: repeat, then check existing connections (AC-6, AC-7)
- [ ] TASK-5 — Log any bugs found in the manual test report
