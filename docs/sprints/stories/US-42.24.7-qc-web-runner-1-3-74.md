## Goal

Check multisig account phase 1 — creating a multisig account, seeing pending requests, and approving them — on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

Multisig account phase 1, the UI part ([#4855](https://github.com/Koniverse/SubWallet-Extension/issues/4855)).

The issue body is an unfilled GitHub template — no description, no acceptance criteria. So the checks below are written from what a multisig account has to do, and they need adjusting against the build before the session starts. The points are set from the title for the same reason.

A multisig account is one address controlled by several signatories, where a set number of them have to approve before a transaction goes through. Phase 1 is the screens for that.

## Before testing

- At least three accounts in the wallet, to be signatories.
- Funds on the multisig address, so a transaction can actually be submitted and approved.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

Setting up a working multisig with a threshold and then walking a transaction through each signatory is most of the effort here.

## Things to check

Creating a multisig account

- [ ] AC-1: A multisig account can be created by picking signatories and a threshold, and the resulting address matches what the chain derives — Android + iOS fresh
- [ ] AC-2: The multisig account appears in the account list, marked so it is not mistaken for a normal account — Android + iOS fresh
- [ ] AC-3: Its balance loads correctly — Android + iOS fresh
- [ ] AC-4: AC-1 to AC-3 pass on Android + iOS upgrade

Approving a transaction

- [ ] AC-5: A transaction started from the multisig account creates a pending request, and it shows with the amount, destination and how many approvals it still needs — Android + iOS fresh
- [ ] AC-6: A second signatory can approve, and the count goes up — Android + iOS fresh
- [ ] AC-7: Once the threshold is reached the transaction goes through and the balance changes — Android + iOS fresh
- [ ] AC-8: Below the threshold the transaction stays pending and no funds move — Android + iOS fresh
- [ ] AC-9: AC-5 to AC-8 pass on Android + iOS upgrade

Upgrade specific

- [ ] AC-10: After upgrading, multisig accounts and any pending requests from before the upgrade are still there and still correct — both platforms
