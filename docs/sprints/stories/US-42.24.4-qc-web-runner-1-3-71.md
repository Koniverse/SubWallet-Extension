## Goal

Check the three items that came into the web-runner with 1.3.71, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

- Token enabling round 2 ([#4247](https://github.com/Koniverse/SubWallet-Extension/issues/4247)) — three fixes: the native token now stays on when the RPC is changed and the network drops; token balances that Subscan supports are detected automatically; and when a network is re-enabled from Settings, tokens that had a balance or were switched on before come back on their own instead of having to be toggled again.
- Library updates ([#4808](https://github.com/Koniverse/SubWallet-Extension/issues/4808)) — dependencies bumped, including axios with its old fallback removed. Nothing changes on screen, but the bump touches every path the app uses to reach the outside world, so the developer asked for the whole user-facing surface to be confirmed across EVM, Substrate, Bitcoin and TON. That scope is written out in the AC below.
- Import from Trust Wallet ([#4762](https://github.com/Koniverse/SubWallet-Extension/issues/4762)) — importing a Trust Wallet seed phrase used to produce different addresses because the two wallets used different derivation paths. The same seed should now give the same addresses in both.

## Before testing

- Trust Wallet installed on a separate device or profile, with a wallet created there, so the same seed phrase can be imported into SubWallet and the DOT addresses compared side by side.
- An account already in the wallet from an ordinary seed phrase import, and one already imported from Trust Wallet, to check what happens when the same seed arrives twice.
- A network whose RPC can be switched, to test the native token staying on.
- Funded accounts on EVM, Substrate, Bitcoin and TON, so a real transaction can be sent on each — the library scope needs all four, and that is the slow part of this story.
- A dApp to connect to, one that can request an EIP-712 typed-data signature.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Test notes

- Tested 2026-09-05 and 2026-09-07 — Mobile, Android and iOS, fresh install and upgrade
- Passed: AC-1 to AC-4 (token enabling), AC-20 to AC-39 (import from Trust Wallet)
- Not run: AC-5 to AC-19 (the library update scope)
- No bugs found

Both halves of this story had their AC rewritten on 2026-09-07, and for the same reason: the originals were written from the issue titles, and the real scope was somewhere else.

The Trust Wallet AC were rewritten against the checklist actually used to test it. The four they replaced only said "compare the addresses on Polkadot and three EVM chains" — true as far as it went, but silent on the screens the import is reached through, what the imported account may do afterwards, and what happens when the same seed arrives twice by two different routes. That is where the behaviour actually is.

The library AC were rewritten against the test scope the developer wrote in [#4808](https://github.com/Koniverse/SubWallet-Extension/issues/4808) itself. The two they replaced said "balances, prices and history load". The developer asks for the whole user-facing surface across EVM, Substrate, Bitcoin and TON, in five areas: account and key management, signing and transactions, network and dApp flows, data fetching, and the version update itself. Fifteen AC now, and it is the larger half of the work left.

What the import does: the account arrives as a solo DOT account whose address matches Trust Wallet. Derive is off, both on the account screen and in the create-account modal. Export offers seed phrase and JSON, and re-importing that JSON gives an account that behaves the same way. Migrate account is not offered. Everything else — receive, send, NFT, swap, stake, dApp signing — works normally.

Importing the same seed twice is refused in the direction it should be: an account already in the wallet, imported again by the same route, gives "Account already exists under the name {Account name}". Coming in by the other route works, and a watch-only or QR account on a different ecosystem from the same seed can still be added either way.
