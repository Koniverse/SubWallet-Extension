## Goal

Check that the XCM routes dropped by ParaSpell v2 are gone from the wallet, and that no route still supported by ParaSpell was removed by mistake.

## Background

This request comes from [ChainList #705](https://github.com/Koniverse/SubWallet-ChainList/issues/705) — remove the XCM routes for chains ParaSpell no longer supports in [XCM API v2](https://paraspell.github.io/docs/supported-chains.html).

This is the clean-up half of the ParaSpell v2 work. The migration itself is tested in [US-42.17](US-42.17-qc-issue-5051-paraspell-api-v2.md) ([issue #5051](https://github.com/Koniverse/SubWallet-Extension/issues/5051)); this story only covers the routes being taken away.

### Routes to be removed

Grouped the way the issue lists them:

**Moonbeam / Moonriver group**

- acala LOCAL GLMR to moonbeam NATIVE GLMR
- acala NATIVE ACA to moonbeam LOCAL xcACA
- polkadot NATIVE DOT to moonbeam LOCAL xcDOT (and back)
- statemint LOCAL USDt to moonbeam LOCAL xcUSDT (and back)
- kusama NATIVE KSM to moonriver LOCAL xcKSM

**Manta group**

- bifrost_dot LOCAL MANTA to manta_network NATIVE MANTA (and back)
- polkadot NATIVE DOT to manta_network LOCAL DOT (and back)
- manta_network LOCAL DOT to moonbeam LOCAL xcDOT (and back)
- manta_network NATIVE MANTA to moonbeam LOCAL xcMANTA (and back)

**Others**

- kusama NATIVE KSM to amplitude LOCAL KSM
- pioneer NATIVE NEER to karura LOCAL NEER

**Testnet (Rococo)**

- rococo NATIVE ROC to hydradx_rococo NATIVE HDX
- rococo NATIVE ROC to rococo_assethub NATIVE ROC (and back)

## Things to check

- [x] AC-1: None of the removed routes above can be selected on the XCM transfer screen — the destination chain no longer shows for that token
- [x] AC-2: Removing these routes does not break the XCM screen — no blank list, no crash, no stuck loading when picking a token that lost a route
- [x] AC-3: Routes that ParaSpell v2 still supports are untouched and still work end to end (send an XCM on at least one route per remaining group)
- [x] AC-4: Tokens involved in the removed routes still show correct balances and can still be sent normally on their own chain
- [x] AC-5: A pending/past transfer on a removed route still shows correctly in transaction history (old history is not broken)
- [x] AC-6: The removed testnet routes (Rococo group) are also gone, checked with testnet mode on
- [x] AC-7: AC-1 to AC-6 hold on a **fresh install** (no prior version/data)
- [x] AC-8: AC-1 to AC-6 hold on an **upgrade** from a previous version (existing accounts/data carried over)
