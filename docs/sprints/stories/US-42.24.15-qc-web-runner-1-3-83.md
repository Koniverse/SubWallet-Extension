## Goal

Check the earning terms and conditions screen, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

## What is in this version

Earning terms and conditions ([#5007](https://github.com/Koniverse/SubWallet-Extension/issues/5007)).

The issue body is empty — just a title. So these checks come from what the build does, and the points come from the title. From the title, this is a terms screen the user has to accept before staking through Earning.

## Before testing

- An account with enough balance to start an earning position.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [ ] AC-1: Starting an earning position shows the terms and conditions before the transaction — Android + iOS fresh
- [ ] AC-2: The terms cannot be accepted without the user acting — the button is off until the box is ticked, or whatever the build requires — Android + iOS fresh
- [ ] AC-3: Declining or going back cancels the flow, and no transaction is sent — Android + iOS fresh
- [ ] AC-4: After accepting, the earning flow carries on and the position is created — Android + iOS fresh
- [ ] AC-5: Whether the terms show again on a later earning attempt matches what the build intends — record which it is — Android + iOS fresh
- [ ] AC-6: The terms text is readable in all supported languages, with no raw keys — Android + iOS fresh
- [ ] AC-7: AC-1 to AC-6 pass on Android + iOS upgrade
- [ ] AC-8: After upgrading, an account with an existing earning position is not blocked by the new terms screen — both platforms
