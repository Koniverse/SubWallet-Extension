## Goal

Check that the deprecated Bittensor root claim type has been removed cleanly, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-86.md).

This is the version the whole update is named after.

## What is in this version

Remove the Bittensor root claim type ([#5045](https://github.com/Koniverse/SubWallet-Extension/issues/5045)) — the Bittensor v4.4.1 chain upgrade deprecated a function the earning code was calling, so it has been taken out.

A removal, so the checks are that the old option is gone and that Bittensor earning still works without it.

## Before testing

- A Bittensor account with a root staking position.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [ ] AC-1: The removed root claim option no longer appears on the Bittensor earning screens — Android fresh
- [ ] AC-2: Bittensor earning still works — the position shows, and stake and unstake go through — Android fresh
- [ ] AC-3: Nothing calls the deprecated function — no error, no stuck loading, no empty screen where the option used to be — Android fresh
- [ ] AC-4: Subnet staking on Bittensor is unaffected — Android fresh
- [ ] AC-5: AC-1 to AC-4 pass on Android upgrade
- [ ] AC-6: AC-1 to AC-4 pass on iOS fresh
- [ ] AC-7: AC-1 to AC-4 pass on iOS upgrade
- [ ] AC-8: After upgrading, an account that had used the old root claim opens without error and its position is correct — both platforms

## Steps

- [ ] TASK-1 — Note the build under test and its web-runner version
- [ ] TASK-2 — Android fresh install: confirm the option is gone, earning still works, subnet staking unaffected (AC-1 to AC-4)
- [ ] TASK-3 — Android upgrade from the previous version, using an account that had used the old claim (AC-5, AC-8)
- [ ] TASK-4 — iOS fresh install: repeat (AC-6)
- [ ] TASK-5 — iOS upgrade from the previous version, same account condition (AC-7, AC-8)
- [ ] TASK-6 — Log any bugs found in the manual test report
