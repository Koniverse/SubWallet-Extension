## Goal

Check the one item that came into the web-runner with 1.3.88, on Android and iOS, on a fresh install and on an upgrade.

Parent: [US-42.24](US-42.24-qc-web-runner-1-3-90.md).

## What is in this version

Update ParaSpell API integration to v2 ([#5051](https://github.com/Koniverse/SubWallet-Extension/issues/5051), [PR #5053](https://github.com/Koniverse/SubWallet-Extension/pull/5053)) — the ParaSpell integration moves to the v2 API. The issue body is one line saying the integration has to align with the latest API version.

ParaSpell is what builds XCM transfers, so an API move touches every cross-chain route rather than one screen. That is why this is an 8 and not a 3: the work is running the routes again, not reading a new screen.

This is the second ParaSpell move in the programme. [US-42.24.12](US-42.24.12-qc-web-runner-1-3-79.md) covered the move to API v1 in 1.3.79 and passed, and [US-42.24.5](US-42.24.5-qc-web-runner-1-3-72.md) covered the move to ParaSpell V5 before that. The same checks apply: the routes still work, the quoted fee matches what is taken, and nothing that worked before has disappeared.

## Before testing

- Balance on both ends of several XCM routes, covering substrate to substrate, substrate to EVM, and at least one bridge type.
- Enough of the native token on each origin chain to pay fees on repeated runs.
- The previous web-runner version installed, with accounts and data, for the upgrade runs.

## Things to check

- [ ] AC-1: XCM transfers still work on the main routes after the API change — Android + iOS fresh
- [ ] AC-2: The fee quoted before sending matches what is actually taken — Android + iOS fresh
- [ ] AC-3: The destination fee is still shown, and the amount that arrives matches the quote — Android + iOS fresh
- [ ] AC-4: No route that worked on the previous version has disappeared from the list — Android + iOS fresh
- [ ] AC-5: A route that cannot be served fails clearly, with a message rather than a stuck screen — Android + iOS fresh
- [ ] AC-6: XCM history shows the same figures the confirmation screen did — Android + iOS fresh
- [ ] AC-7: AC-1 to AC-6 pass on Android + iOS upgrade
- [ ] AC-8: After upgrading, XCM history from before the upgrade is still readable and its figures are unchanged — both platforms
