| most recent failure | **2026-10-27 00:50**, today |
| last successful `scheduler-dev.yml` run | 2026-10-23 09:54 — a **manual** dispatch from `dev` |
| `main`'s newest commit of any kind | **2026-09-18 13:53** |

**The cause and the cure have both been known since 10-21** ([notes/2026-10-21.md](2026-10-21.md)),
and the cure is sitting on the wrong branch. GitHub schedules workflows from the **default branch**,
so `dev` having the fix changes nothing for any scheduled run — which is why `scheduler-dev.yml`
also fails on schedule while succeeding when dispatched by hand from `dev`. **Production earning
data has been frozen 39 days.**

### Why this is the clock to watch

**Taostats' old API paths stop on 2026-11-09 — 13 days from today.** `dev` already builds
`validator.json` from the chain instead of that path, and **released clients still read
`validator.json`**. So `main` needs two things before 11-09: the deploy fix, and the
build-from-chain change. One merge of `dev` → `main` carries both.

If 11-09 arrives first, released clients lose validator data — and the scheduler that would
publish a correction is the same one that has not run since September.

**One caveat on the 10-20 manual dev commit**: [notes/2026-10-21.md](2026-10-21.md) records that
`0d929d1374` carries PR #5113's minimums and subnet APR but was never deployed and **must be
regenerated first**, because its subnet targets carry root's `minBond` (fixed later by #5113's
`f19b9e8318`). A `dev` → `main` merge should not carry that artefact unregenerated.

### What the perf commit actually measured

`ce80a2ebff` is worth reading for the number in it, not the fix: a position read lists **every
subnet for every account**, nearly all without stake, and each one was written to the position

held) and again only when a stake there is gone; a position with stake is still sent every read.
That is the kind of cost that never appears as a bug report, and the commit quantified it rather
than asserting it.
