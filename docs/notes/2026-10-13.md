- [x] **R-1 One pruned block still breaks the whole update.** One failed block read in the
  per-tx lookup
  ([`multisig-service/index.ts:484`](https://github.com/Koniverse/SubWallet-Extension/blob/f836222c51ead536bae5a2ee59da30acef40512c/packages/extension-base/src/services/multisig-service/index.ts#L484))
  rejects the surrounding `Promise.all`, so the callback never runs. The new `unresolvedTxMap` after
  it never receives the failed tx, so the keep-last-known-data path US-18.5 AC-2 describes is not
  reached. **Reproduced:** A has executed and B's block is pruned → A still shows as pending.
  **Fix:** catch per tx, and pass the storage metadata of a tx that could not be read down to
  `unresolvedTxMap`. Left as is, the state can stay stuck until the RPC changes.
- [x] **R-2 A stale read that returns late can overwrite a newer state.** The subscription callback
  is async with no ordering check, and the status update
  ([`:698`](https://github.com/Koniverse/SubWallet-Extension/blob/f836222c51ead536bae5a2ee59da30acef40512c/packages/extension-base/src/services/multisig-service/index.ts#L698))
  accepts old data. **Reproduced:** the newer run writes `RESOLVED`, then the older run finishes →
  the status goes back to pending, the tx reappears in the cache, and the notification stays marked
  read. **Fix:** drop the results of a superseded snapshot, and keep notification writes in order.
