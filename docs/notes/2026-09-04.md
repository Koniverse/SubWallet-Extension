## B. Item 2 hides two bugs behind one checkbox

This is the thing worth acting on first, because it is the one that can silently lose work.

The comment's item 2 is **titled** as one bug and **described** as a different one:

| | |
| --- | --- |
| Title | *"Please check the turn on/off network"* — this is `BUG-42.24.2-02`: **the toggle does not respond, on every network** |
| Body | *"The network never connects. The badge is the crossed-out disconnected icon even though the toggle is on"* — this is `BUG-42.24.2-01`: **Acurast connects but shows the wrong badge** |

They are different failures with different blast radii — one is a **dead control on all networks**, the
other is a **wrong status badge on one network**. A fix for either one makes the checkbox look
tickable, and **ticking it would close the other without anyone noticing**.

**Split item 2 into two checkboxes on the tracker comment.** That is a one-minute edit and it is the
only thing standing between "the toggle works again" and a permanently-lost badge bug.

The report says `BUG-42.24.2-01` and `-02` **"cleared on their own during the session — the networks
can be turned on again"**, and kept them logged because they are real. The comment, written the same
day, still lists them as open items to check. Both can be true — intermittent bugs are still bugs —
but whoever picks item 2 up should know it may not reproduce on first try, or they will close it as
*cannot reproduce*.

The report says it plainly and it deserves to be surfaced rather than left in a summary paragraph:

> *BUG-42.24.2-02 and -03 happen on every network and every token, so they may not belong to this
> chain-list version at all.*

Both are logged under [US-42.24.2](../sprints/stories/US-42.24.2-qc-web-runner-1-3-69.md), whose scope
is **web-runner 1.3.69 / chain-list v0.2.122**. If a dead network toggle and a missing price chart
affect *every* network and *every* token, the likely causes are the **Mobile app shell** or something
that predates this whole backfill — not a chain-list bump that added Acurast, TRAC and vMANTA.

**This matters for where they get fixed**, not just for tidiness. Filed under a web-runner sub-task,
they will be worked as part of a 19-version backfill queue. If they are Mobile-app bugs they belong
on their own Mobile issues and can be fixed now, in parallel, by someone else.

**Cheapest test:** install the *previous* Mobile build — the one before this web-runner bump — and try
a network toggle and a token detail screen. If both fail there too, they are not this backfill's.
