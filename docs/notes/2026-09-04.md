checkbox"*. The comment was already there when that was written. The cause is mechanical: the tracker
had been a single comment for six days, the read script indexed `comments[0]`, and when the tester
opened a **second comment** to add an item after the list had closed, the script kept reporting
twenty items and no error. **A negative finding needs the same corroboration as a positive one** —
`LESSONS §69` in the same shape as the ChainList PR miss: the query looked in one place and the
answer was reported as if it had looked everywhere.

**And the timestamp on yesterday's entry was not measured.** It reads *"Re-read 2026-09-08 17:20
+07"*; the issue's own `updated_at` at that fetch was 11:05 UTC — 18:05 +07 — so the read cannot have
happened before then. The time was carried over from an earlier `date` call instead of a new one.
Stamp a read with the clock, or do not stamp it.

  risk in a note nobody reads before ticking does not prevent it.
