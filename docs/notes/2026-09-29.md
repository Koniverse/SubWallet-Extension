**Six testnets came back.** The drop from 67 to 61 is commit `08a548fd85` — *"Reactivate testnets

**A whole new section appeared: Bittensor subnets synced with taostats.** 102 subnets changed —

**IBP is gone entirely.** `*.ibp.network` returns NXDOMAIN and `*.dotters.network` SERVFAIL, so

### Why it is worth a note rather than only a row

Deactivating **67 chains** is data, not code, so it ships without a release
([FR-34](../PRD.md#epic-4--chain-management) working as designed). But it is the most
user-visible thing in flight: chains vanish from the wallet's list. The reasons are recorded
per chain and they are mostly *the chain is gone*, not *our endpoint broke* — Moonbeam and
Moonriver shut down 31/07/2026 with GLMR migrated to Base, Centrifuge migrated to EVM under CP149,
Manta Atlantic was deprecated 01/08/2026, Interlay has been halted ~63 days, KILT's lease runs out
05/2026. That is a real shrinkage of the supported set, and nothing in this repository would
otherwise say so.

**The method is stated, which is the part worth keeping.** Every endpoint got a real call —
Substrate `chain_getBlockHash(0)` compared against `genesisHash`, EVM `eth_chainId` — plus a
latest-block-time check to catch halted chains, 3 retries with IPv4 forced. **HTTP 429 was treated
as alive**, which is the right call and the kind of decision that is usually invisible: a rate
limit is not a dead endpoint, and a sweep that counted it as one would have removed working RPCs.

## B. Four syncs in a row missed #710, because every sweep filtered on `createdAt`

#710 was opened **2026-08-25** and edited into its current shape on **2026-09-28**. Every status
sweep in this session asked GitHub for issues *created* after a recent date —
`select(.createdAt > "2026-09-25")` and similar — so an issue created in August and **actively
worked yesterday** was invisible. The sweeps that reported *"no new issues"* were answering a
narrower question than the one being asked.

It surfaced only because the user pasted the link.

**This is [LESSONS §69](../LESSONS.md) in its fifth shape.** The previous four were about trusting
a field GitHub hands you. This one is about **the query**: a filter is a claim too, and
`createdAt` answers *what is new* while the question was *what is live*. An empty result from the
wrong filter is indistinguishable from an empty result from the right one.

**The fix is one word**: sweep on `updatedAt`, not `createdAt`. Run against both repos today it
returns exactly three ChainList issues — #710, #711, #712 — and one Extension issue, #5093. The
`createdAt` version returned two and one, and the one it dropped was the largest piece of work in
flight.

**A second thing the same sweep dropped**: [Extension PR #5010](https://github.com/Koniverse/SubWallet-Extension/pull/5010)
has appeared in every `gh pr list` output this session, open since July, and was never read because
it was old. Its subject is the same as #710's.

**And one near-miss worth recording.** Grepping the docs for `#710` returns a hit in
[US-4.4](../sprints/stories/US-4.4-substrate-parachain-registry.md) — *"Add default option for
parachain inflation information", 0.6.7, done*. That is **Extension #710**, an unrelated issue in a
different repo. Two repos, one number; a grep for a bare issue number cannot tell them apart, and
taking that hit at face value would have closed this out as *already covered*.

## C. Extension PR #5096 carries a *"revert before commit"* change that disables FR-34

[PR #5096](https://github.com/Koniverse/SubWallet-Extension/pull/5096) —
*"[Issue-710-chainlist] Maintenance of chainlist"*, opened **2026-09-29 04:43** by tunghp2002 onto
`subwallet-dev`, branch `koni/dev/issue-710-chainlist`: **2 commits, 6 files, empty body, no
review.** This is the Extension half of #710 that yesterday's note said would be needed.

**It is not a pin bump like #5089.** #5089 moved `ChainListVersion` in
`chain-service/utils/patch.ts`; #5096 does not touch that file at all. It moves the **npm
dependency** in four `package.json` files plus `yarn.lock`:

```
-    "@subwallet/chain-list": "0.2.131",
+    "@subwallet/chain-list": "0.2.132-beta.2-pr-713-7aa00e22",
```

That target is **a PR build, not a release** — `beta.2-pr-713-<sha>` names PR #713's head. Correct
for testing, and not a thing to merge.

### The part that matters

The sixth file is `packages/extension-base/src/services/chain-service/index.ts`, **+10/−8**, and it
comments out the body of `handleLatestData()`:

```js
// TODO: TEMP - disabled online chain data override to test local chain-list RPCs. Revert before commit.
// this.fetchLatestChainData().then((latestChainInfo) => {
//   this.lockChainInfoMap = true;
//   this.handleLatestChainData(latestChainInfo);
//   ...
```

with `fetchLatestChainData` itself now carrying
`// @ts-ignore TODO: TEMP - unused while online chain data override is disabled. Revert before commit.`

**That is [FR-34](../PRD.md#epic-4--chain-management) switched off.** The online chain-data
override is the capability
[US-4.3](../sprints/stories/US-4.3-auto-update-chain-list-and-token-metadata.md) delivers and the
reason chain data can change without an extension release. [EPIC-4](../sprints/epics/EPIC-4.md)
writes it as a cross-cutting invariant — *chain list and token metadata are served from the
static-data cache / CDN proxy, never hard-coded into the bundle* (AD-23, AD-25). With
`fetchLatestChainData()` commented out, the wallet would run on whatever is baked into the bundled
`@subwallet/chain-list` and **nothing served from the CDN would ever reach it.**

**The author already knows** — the comment says *Revert before commit*, twice. This is scaffolding
for testing #713's RPCs against a local list, which is a sensible thing to do. **The risk is not
the change, it is the merge**: the PR is open with an empty body, no review and no draft marker,
and the branch name reads like the routine companion to #5089. Nothing on the PR says *do not
merge* except a comment inside the diff.

### What would make it safe

Any one of these closes it: mark #5096 **draft**; or say *testing only, do not merge* in the body;
or drop the `chain-service/index.ts` commit and keep only the dependency bump, which is the part
that will eventually be real — **against a released `0.2.132`, not `0.2.132-beta.2-pr-713`.**

**Recorded, not acted on.** Nothing here touches #5096; this is a note so the next reader of the
PR sees what is in it.
